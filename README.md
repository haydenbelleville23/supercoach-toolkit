# Footynomics

Price projections, cash cows and trade planning for AFL SuperCoach. Not affiliated with the AFL or the official AFL SuperCoach competition.

This is a [Next.js](https://nextjs.org) project bootstrapped with [`create-next-app`](https://nextjs.org/docs/app/api-reference/cli/create-next-app).

## Getting Started

First, run the development server:

```bash
npm run dev
# or
yarn dev
# or
pnpm dev
# or
bun dev
```

Open [http://localhost:3000](http://localhost:3000) with your browser to see the result.

You can start editing the page by modifying `app/page.tsx`. The page auto-updates as you edit the file.

This project uses [`next/font`](https://nextjs.org/docs/app/building-your-application/optimizing/fonts) to automatically optimize and load [Geist](https://vercel.com/font), a new font family for Vercel.

## Debug: view the site "as of" a round

Set `DEBUG_AS_OF_ROUND` to a round number (1-24) to see every page exactly
as it would have looked straight after that round:

```bash
DEBUG_AS_OF_ROUND=10 npm run dev
```

On Windows PowerShell: `$env:DEBUG_AS_OF_ROUND = "10"; npm run dev`.

- Round N is treated as the last completed round. Scores, prices, price
  changes and games after Round N are removed, players added later (such as
  mid-season draftees) do not exist, and later rounds are estimated by the
  scaled model from Round N's data and price total.
- The data is trimmed at build time (`.debug-data/round-N`, generated by
  `scripts/build-as-of-data.ts` from `next.config.ts`), so later rounds
  never reach the browser.
- The live-score feed is ignored, and an amber "Debug: viewing as of
  Round N" banner shows on every page.
- Unset (the default) changes nothing. It only turns on where the variable
  is explicitly set, so **do not set it on Vercel**. Restart `npm run dev`
  after changing it.

### Round 10 debug mode (local)

The lock above, ready to switch on and off without editing anything:

| Command | What it does |
| --- | --- |
| `npm run dev:r10` | Dev server as of Round 10 (banner shows). |
| `npm run dev:live` | Dev server with the lock explicitly cleared: live data, no banner. |
| `npm run dev` | Uses `DEBUG_AS_OF_ROUND` from `.env.development.local`, if you have one. |

Both scripts run `scripts/dev.mjs`, which works the same in Windows
PowerShell, macOS and Linux. Options after `--` go to `next dev`
(for example `npm run dev:r10 -- -p 3001`).

To make plain `npm run dev` start locked, put this in
`.env.development.local` (gitignored, never committed):

```bash
DEBUG_AS_OF_ROUND=10
```

This is `.env.development.local`, not `.env.local`: Next.js reads
`.env.local` for `next build` too, so a lock there would also lock local
production builds. `.env.development.local` is only read by `next dev`.
Delete the line (or use `npm run dev:live`) to go back to live data.

Production and Vercel previews are controlled only by Vercel's environment
variables. `DEBUG_AS_OF_ROUND` isn't set in any committed file,
`next.config.ts` or `vercel.json`, and env files aren't deployed.

Development backtest: `npm run backtest:as-of -- 10` prints the Projector's
projections as of Round 10 beside the prices actually published later, with
the error per round (`--player <id>` for one player, `--mode` to change the
projection), and writes a CSV to `scripts/output/`.

## Analytics (Vercel Web Analytics)

The site counts page views with Vercel Web Analytics (`@vercel/analytics`,
`components/analytics/SiteAnalytics.tsx`). It only loads on the production
deployment (`VERCEL_ENV=production`) and never while `DEBUG_AS_OF_ROUND`
is set (`shouldTrackAnalytics` in `lib/analytics.ts`), so previews, local
development and debug builds send nothing. The internal pages
(/magic-number, /engine, /debug) are dropped before sending. No custom
events.

To turn it on in the dashboard:

1. Open the project in the Vercel dashboard.
2. Open the **Analytics** tab.
3. Click **Enable Web Analytics** (the **Enable** button), then redeploy.
   Vercel adds its `/_vercel/insights/*` routes on the next deployment.

The Hobby plan includes 50,000 events a month, shared across all projects
on the account. Hobby can't buy more: once the limit is passed, collection
pauses (after a short grace period) until it resets, or until you move to
Pro. See [Vercel's limits and pricing](https://vercel.com/docs/analytics/limits-and-pricing).

What it records is described on [/privacy](app/privacy/page.tsx), based on
[Vercel's Web Analytics privacy page](https://vercel.com/docs/analytics/privacy-policy).
